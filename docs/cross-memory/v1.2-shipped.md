This document is the closing artifact of the cross-memory v1.2 build. ## Shipped

Cross-memory v1.2 adds one new subcommand (`reflect`), one new agent intent (`distill`), two new per-project files (`reflect_declined.md` and `state.toml`), one staleness nudge, and one global-instructions edit. All v1 and v1.1 artifacts remain unchanged.

### M0 — Doc-gap prerequisite (`~/.claude/CLAUDE.md`)

Before the reflect filter can reference a categorical exclusion corpus, a stable addressable home for the "What NOT to save in memory" rule must exist.

**Deliverable.** A new `## What NOT to save in memory` section in `~/.claude/CLAUDE.md`. The section lists four exclusion categories with one-line rationales:

- **Project goals** — project-specific and ephemeral; where durable, they reduce to user preferences.
- **Transient session state** — tool outputs, intermediate calculations, debugging scratch.
- **Secrets and credentials** — any value that should not leave its source context.
- **Episodic conversation logs** — back-and-forth that records the journey, not the destination.

The heading is byte-identical to `## What NOT to save in memory` (the agent brief reads by exact heading match). The section does not cite planning-doc labels or internal ADR identifiers.

This section is user-installed at execute time (M0.implement.1). It is outside the agent's SC-21 runtime write scope. The reflect filter reads it as Reference Set D (LLM-prompt-applied), described further under the M3 section below.

**Note on future refinement.** The starter wording is a v1.2 deliverable. Refinement of the rule (per Gap G10 of the scoping doc) waits for real decline-ledger evidence — a v1.2.1 or v1.3 doc-sync pass.

### M1 — Substrate (`skills/cross-memory/SKILL.md`)

The substrate milestone lays down the data shapes that M2 (agent contract) and M3 (reflect subcommand) consume. No user-visible surface changes land in M1 alone.

#### `reflect:` namespace in the Config section

Four new documented fields under a `reflect:` namespace in `## Config`:

| Field | Default | Purpose |
| :--- | :--- | :--- |
| `reflect_staleness_threshold_days` | `30` | Days since last reflect run before the staleness nudge fires. Also the fallback window for `--since-last-reflect` when `last_reflect_at` is unset. Distinct from `staleness_threshold_days` (90 days, memory `verified_at` staleness — a different concept). |
| Slug-overlap threshold | `0.85` | Anti-redundancy disjunctive trip threshold for slug signal. Configurable under `reflect:` in `~/.cross-memory/config.yaml`. |
| Tag-overlap threshold | `0.8` | Anti-redundancy disjunctive trip threshold for tag signal. |
| Body-token Jaccard threshold | `0.7` | Anti-redundancy disjunctive trip threshold for body signal. |

`~/.cross-memory/config.yaml` is **user-installed** — it is not part of `tooling/deploy-manifest.json`. Users add the `reflect:` namespace themselves. Old configs without the section fall back to the documented defaults at runtime.

#### `state.toml` schema (`~/.cross-memory/projects/<slug>/state.toml`)

Lazy-created on the first completed reflect run. Written by the skill, not the agent. Co-located with `reflect_declined.md` and the per-project `MEMORY.md`.

Schema fields (under `[reflect]`): `last_reflect_at` (ISO 8601 UTC; absent when reflect has never run), `last_reflect_candidate_count` (integer), `last_reflect_run_id` (opaque string).

**Absent-or-unparseable treatment.** Both `init` and `doctor` treat a missing or unparseable `state.toml` as "unset" — the staleness nudge does not fire.

**Empty-project carve-out.** When reflect exits with zero raw candidates from any source, the skill exits before any `state.toml` write. `last_reflect_at` is unchanged. On an all-filtered run (N raw, zero surfaced), `state.toml` IS updated — the run completed successfully even though the interactive loop was skipped.

#### `reflect_declined.md` ledger schema (`~/.cross-memory/projects/<slug>/reflect_declined.md`)

Lazy-created on first decline. Append-only. Co-located with `state.toml`.

Format: Markdown with per-entry frontmatter blocks delimited by `---`. Each decline event becomes one new block.

**Entry schema fields:** `declined_at` (ISO 8601 UTC), `candidate_id`, `proposed_name`, `category`, `scope`, `tags`, `body_preview`, `source_evidence`, `run_id`.

Written by the skill after `decline <id>` returns from the interactive loop. The agent never writes to this file.

**Matching strategy.** During a subsequent distill pass, the agent parses each ledger entry as a `(proposed_name, category, scope, tags, body_preview)` tuple and applies the three-signal filter (slug-overlap, tag-overlap, body-Jaccard) in turn. A new candidate that crosses any threshold drops with reason `declined-redundancy`.

No on-disk deduplication — the filter handles redundancy across subsequent runs.

#### Filter test fixtures (`skills/cross-memory/test-fixtures/reflect/`)

Defined at M1.implement.4 to give the M3 verify tasks reproducible controlled inputs. The fixture directory co-locates with the skill and is covered by the deploy manifest's `skills/**/*.md` and `skills/**/*.yaml` globs.

Fixture set covers: slug-collision cases, tag-overlap cases, body-Jaccard threshold cases, supersede-collision cases, frozen `git log` snapshot, frozen `docs/plan/**` slice, frozen handoff slice, frozen canonical-store slice.

`M3.verify.2`, `M3.verify.3`, and `M3.verify.5` consume these fixtures.

### M3 — `reflect` subcommand (`skills/cross-memory/SKILL.md`)

Reflect's full body lands in `skills/cross-memory/subcommand-reflect.md`; the SKILL.md surface adds a `## Subcommand: reflect` pointer block after the `## Subcommand: audit` pointer. `reflect` is the ninth subcommand peer of `audit`, added to the parser allowlist.

#### Router and flag grammar

```
/cross-memory reflect \
  [--from-session <session-id>] \
  [--since-last-reflect] \
  [--from <path>] \
  [--scope <user-global|project:<slug>|harness:<name>>] \
  [--staleness-days <N>] \
  [--verbose]
```

- `--from-session` and `--since-last-reflect` are mutually exclusive. Both invoke Source 1 (transcript ingestion). Both **error at parse time** under Cursor/generic: `error: --from-session is Claude-Code-only; current harness is <name>`.
- `--from <path>` is always available under all harnesses; multiple arguments union into a single source set.
- `--scope` defaults to `project:<active-slug>`.
- `--verbose` prints per-candidate filter decisions.
- `--non-interactive` is not parsed at v1.2 — the grammar accommodates it without restructuring (v1.3).
- `--dry-run` is not parsed at v1.2 (intent-deferred to v1.3 — see Deferred section).

Help output and the unknown-subcommand error message gain the new entry.

#### Four-source pipeline

| Source | Availability | Description |
| :--- | :--- | :--- |
| Source 3 — git + working-tree | All harnesses | Skill runs read-only `Bash` commands (`git log`, `git diff --stat`, `git log -- <doc paths>`) bounded by last 90 days or 200 commits. Working-tree convention probes: `pyproject.toml`, `package.json`, `.editorconfig`, `tsconfig.json`, `ruff.toml`, `mypy.ini`, `.github/workflows/**`, `tooling/deploy-manifest.json`, top-level directory listing. Staged in `_tmp_reflect_source3_<timestamp>.md` before agent dispatch. |
| Source 4 — plan docs, handoffs, dispatch logs | All harnesses | Three globs: `docs/plan/**/*.md`, `docs/cross-memory/handoff*`, `docs/ops-dispatch-log*`. Bound: 50 files per glob; over-bound files reported in a `truncated:` field. Agent reads each matched file lazily during distillation. |
| Source 1 — Claude Code transcripts | Claude Code only (opt-in) | `.jsonl` session transcripts at `~/.claude/projects/<active-slug>/<id>.jsonl`. Invoked by `--from-session <id>` (named session) or `--since-last-reflect` (sessions newer than `last_reflect_at`). Bound on `--since-last-reflect`: 20 sessions. Structural pre-check runs before agent dispatch: verify file exists, parses as one JSON object per line, has minimal expected keys. Pre-check failure → structured warning, fallback to Sources 3+4 only. |
| Source 5 — explicit seed | All harnesses | `--from <path>` accepts a file or directory; multiple arguments union. Bound: 100 paths total or 10 MB total content. Non-existent or unreadable paths error before agent dispatch. |

Source 5 content is read by the agent during distillation but is **not** pre-redacted by the skill. Redaction applies only at Gate 2 of `save <id>`. The body-preview may surface unredacted content from the source path — users should curate `--from` paths accordingly.

An unprompted full transcript scan is never performed under any harness.

#### Report rendering

The skill receives the agent's fenced-markdown candidate table and renders it to chat. Report columns: `id`, `type`, `category`, `scope`, `proposed-name`, `body-preview` (160 chars, `…` truncation), `source-evidence` (commit SHA, file path + line range, or transcript message id), `flags` (includes `would-supersede <existing-id>` when applicable).

Deterministic sort order: by category, then by `proposed-name` lexicographically (AC15 — reproducible candidate set given identical inputs and reference sets).

**Zero-candidates cases:**

- Empty project (no sources): `No candidates surfaced — no eligible input signal found.` No interactive loop; no `state.toml` or `reflect_declined.md` write.
- All-filtered (N raw, zero surface): `N candidates generated, all filtered as redundant against {canonical | archive | declined | excluded}.` No interactive loop; `state.toml` IS updated.

#### Interactive loop

The report enters an interactive loop accepting four commands per candidate:

| Command | Behavior |
| :--- | :--- |
| `save <id>` | Routes through the existing save pipeline (Gate 3 → Gate 4) identically to a direct `/cross-memory save` invocation. |
| `decline <id>` | Appends a structured entry to the per-project `reflect_declined.md` ledger. |
| `edit <id>` | Opens a minimal field-tweak surface (name, body, tags, scope) and re-enters Gate 3 on confirmation. An aborted edit leaves the candidate unchanged. |
| `done` | Exits the loop. Candidates neither saved, declined, nor edited are recorded as "unactioned" in the run log but NOT written to `reflect_declined.md`. They may re-surface on a subsequent run. |

Per-candidate confirmation defaults to **N** (conservative). The user must take explicit action to save.

#### Supersede flagging

When a generated candidate matches an existing canonical-store entry strongly enough to be considered a supersede (the same overlap signals as the filter but evaluated independently of the drop threshold), the candidate appears flagged `would-supersede <existing-id>`.

The user must explicitly enter the supersede branch (via `save` on a flagged candidate, which routes into the v1.1 supersede flow) or skip. Silent supersedes are forbidden.

**Supersede-on-declined collision.** If a candidate would supersede an existing entry AND matches an entry in `reflect_declined.md`, the decline ledger takes precedence: the candidate drops at the filter stage before the supersede check runs. The user is not asked twice.

#### Deterministic anti-redundancy filter

A post-generation deterministic filter drops candidates whose slug-overlap + tag-overlap + body-token Jaccard exceeds threshold against **three deterministic reference sets — the canonical store filtered to relevant tiers, `~/.cross-memory/archive/`, and the new per-project `reflect_declined.md` ledger — plus one LLM-prompt-applied exclusion corpus drawn from `~/.claude/CLAUDE.md`'s `## What NOT to save in memory` section.**

Three deterministic reference sets:

- **Set A — canonical store.** Filtered to: `project:<active-slug>` + `harness:<active-harness>` + `user-global`.
- **Set B — archive.** All entries under `~/.cross-memory/archive/`.
- **Set C — decline ledger.** The per-project `reflect_declined.md` for the active project.

Three canonical reference sets (A, B, C) feed the deterministic filter. The LLM-prompt-applied corpus (Set D) suppresses candidates categorically during raw-candidate generation, before the deterministic filter sees the candidate list.

Default thresholds: slug 0.85, tag 0.8, body-Jaccard 0.7. Disjunctive trip — any one signal crossing its threshold drops the candidate. Configurable per-machine via `config.yaml` under the `reflect:` namespace.

**Pattern taxonomy.** Candidates belong to exactly one of four categories: `architectural-decisions`, `conventions-implicit-in-code`, `workflow-patterns-from-successful-runs`, `user-preferences-from-feedback-patterns`. Project goals are explicitly excluded — a candidate whose category resolves to project goal must be dropped. Reaching the user-facing report with a project-goal category is a filter violation.

### M4 — Staleness nudge (`skills/cross-memory/SKILL.md`)

#### `init` Step 4.5

A new `### Step 4.5 — Reflect staleness check` subsection between Step 4 (sentinel write) and Step 5 (summary output). Reads `state.toml`. When `reflect.last_reflect_at` is set and `(now − last_reflect_at) > reflect_staleness_threshold_days`, emits:

```
Tip: it's been <N> days since reflect ran — run /cross-memory reflect to surface candidates.
```

Suppresses cleanly when `state.toml` is absent, unparseable, or `last_reflect_at` is missing (treat unset as "fresh," never as "stale").

#### `doctor` footer with `reflect_staleness_hint` JSON field

A footer line below the overall-verdict line in all four modes (default, pre-deploy, post-deploy, targeted). In human-readable output: same hint text as `init` Step 4.5. In `--json` mode: a `reflect_staleness_hint` top-level field with sub-fields `fired` (boolean), `days_since_last_reflect` (integer or null), `threshold_days` (integer), `message` (string, omitted when `fired: false`).

Neither `init` nor `doctor` invokes `reflect`. The nudge is suggestive only.

**Cross-harness applicability.** Harness-agnostic. The check reads `~/.cross-memory/projects/<slug>/state.toml`, which exists on every harness. The hint fires identically under Claude Code, Cursor, and generic.

### Step 0 — Preconditions

Before running the three steps below, confirm the following are true:

1. **Deploy v1 + v1.1 + v1.2.** Run `tooling/deploy.ps1` (Windows) or `tooling/deploy.sh` (macOS/Linux) to install all skill and agent files to `~/.claude/`.
2. **Bootstrap a test project.** Run `/cross-memory init` on a test project. Confirm the store is present and the sentinel block is written.
3. **Save a test memory.** Run `/cross-memory save` with any scope. Confirm the memory lands in `~/.cross-memory/`.
4. **Provide Source 4 corpus.** Commit a couple of `docs/plan/*.md` files to the test project (these are consumed as Source 4 by reflect).
5. **Confirm deploy-manifest coverage (r2 §4.1).** Verify that `tooling/deploy-manifest.json` covers every new RUNTIME file v1.2 introduces. The manifest covers RUNTIME files that ship to the user's installation (`~/.claude/skills/cross-memory/` and `~/.claude/agents/`). Documentation artifacts under `docs/` are NOT in the manifest — they live in the repo only. Walk the manifest with `grep` or `Read` to confirm:
   - `agents/cross-memory.md` is covered by the `agents/*.md` glob.
   - `skills/cross-memory/SKILL.md` and all subsection files are covered by the `skills/**/*.md` glob.
   - `skills/cross-memory/test-fixtures/reflect/` tree is covered by the `skills/**/*.md` glob.
   - `~/.cross-memory/config.yaml` is explicitly NOT in the manifest (user-installed).

### Step 1 — Reflect walk in Claude Code

Run `/cross-memory reflect` under the Claude Code harness (no flags on the first pass):

```
/cross-memory reflect
```

Assert the following before moving to Step 2:

- Candidates surface from Sources 3 and 4 by default. Source 5 (`--from <path>`) is optional; if used, candidates from the specified path also appear. Transcript-sourced candidates (Source 1) appear only when `--from-session` or `--since-last-reflect` is passed.
- Exercise all four interactive loop commands against different candidates:
  - `save <id>` — routes through Gate 3 → Gate 4 identically to a direct `/cross-memory save`.
  - `decline <id>` — writes a structured entry to `~/.cross-memory/projects/<slug>/reflect_declined.md`. Confirm the file is created on first decline.
  - `edit <id>` — opens the field-tweak surface; confirm that aborting leaves the candidate unchanged.
  - `done` — exits the loop. Confirm unactioned candidates are not written to `reflect_declined.md`.
- After exiting, confirm `~/.cross-memory/projects/<slug>/state.toml` exists and `last_reflect_at` has advanced to approximately now.
- Confirm `~/.cross-memory/projects/<slug>/reflect_declined.md` exists and contains one entry per `decline` action taken.

### Step 2 — Staleness-nudge walk

1. Manually edit `~/.cross-memory/projects/<slug>/state.toml` and set `reflect.last_reflect_at` to a date 40 days in the past (ISO 8601 UTC, e.g., `2026-04-03T00:00:00Z`).
2. Run `/cross-memory init`:
   ```
   /cross-memory init
   ```
   Assert: the staleness hint fires in the summary output with N=40 (or similar elapsed count). Assert `init` prints the hint with the verbatim text: `Tip: it is been N days since reflect ran — run /cross-memory reflect to surface candidates.`
   > The "it is been" phrasing reflects the SKILL.md spec verbatim. A future v1.2.1 / v1.3 doc-sync pass may normalize this to "it's been" (the grammatically standard form); for v1.2 acceptance, the spec-as-implemented is the canonical text.
3. Run `/cross-memory doctor`:
   ```
   /cross-memory doctor
   ```
   Assert `doctor` prints the same hint as a footer + `--json` includes the `reflect_staleness_hint` field with `message` set to the same text.
4. Run with `--json` and assert the `reflect_staleness_hint` field is present with `fired: true`, `days_since_last_reflect` set to approximately 40, and `threshold_days` set to the configured threshold (default 30).
5. Restore `state.toml` to the current timestamp before proceeding.

### Step 3 — Cursor parity walk

Switch to the Cursor harness (via `--harness cursor` flag or by running from within Cursor's composer) and run:

```
/cross-memory reflect
```

Assert the following:

- Sources 3 and 4 ingest correctly. No `.jsonl` files are touched.
- Source 5 (`--from <path>`) is available and works.
- Assert `--from-session` and `--since-last-reflect` both error with the combined message at parse time: `error: --from-session and --since-last-reflect are Claude-Code-only flags; current harness is cursor`.
- The interactive loop (`save`, `decline`, `edit`, `done`), the anti-redundancy filter, supersede flagging, and `state.toml` write all behave identically to the Claude Code walk in Step 1.
- The staleness nudge in `init` and `doctor` fires identically under Cursor (same hint text, same threshold logic).

### Failure routing

If any step fails, route back to the milestone that owns the failing surface. Do not attempt to patch forward.

| Failed step | Routes back to |
| :--- | :--- |
| Step 0 (preconditions, deploy manifest) | Environment or deploy issue — not a v1.2 milestone defect. Resolve the deploy configuration and re-run Step 0. |
| Step 1 (reflect walk in Claude Code) | M3 — re-dispatch the failing M3 implement or verify task. |
| Step 2 (staleness-nudge walk) | M4 — re-dispatch the failing M4 implement or verify task. |
| Step 3 (Cursor parity walk) | M5 — re-dispatch the failing M5 implement or verify task. |
