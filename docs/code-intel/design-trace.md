## Minor Observations (Non-Blocking)

These items are noted for completeness but do not affect the PASS verdict:

1. **R2 / Q3 — "keystone" label in the agent body.** The ADD labels `impact_analysis` as the keystone query at multiple points. The agent body's quick-reference card and Query Handlers section present all six query types equally; the keystone designation is not explicitly called out in the agent body itself. This is a documentation-style gap, not a behavioral one — the implementation treats the query like the others, which is correct.

2. **R10 rows 8-9 — refusal message format not illustrated.** The failure-mode walkthrough (M5.6) notes that the Output Format Examples section in the agent body shows only three formats: a successful `find_callers` response, the malformed-brief refusal, and the write-allowlist violation. The DB-corrupted (row 8) and query-timeout (row 9) refusal message formats are not illustrated with inline examples. The posture is fully specified in the Failure Matrix; only the exact prose template is absent. Noted by M5.6, not re-assessed here.

3. **`agents/README.md` agent count.** The README counts were not updated when `code-intel` was added (the roster now has 20 agents, not 19 as some prose in the ADD references). However, the README table correctly lists `code-intel` in its roster row (line 21), so the count discrepancy is only in the surrounding prose (the ADD's phrasing "the other 19 agents"). This is pre-existing prose in a doc that is outside the implementation surface and does not block the PASS verdict.
